# features-customization.md —— 自定义能力与产品定位

> 本文件回答两件事：
> ① **这个产品是什么**（默认主题 vs 自定义框架的关系）
> ② 用户能自定义到什么程度、成本是多少

---

## 1. 定位：默认主题是主菜，框架是留给别人的空间

```
┌─────────────────────────────────────────────────────┐
│  主产品：一套完整的 Boujoy 主题                        │
│  · 装上就好看，零操作                                 │
│  · 开屏动画 + 风格界面 + 对话动效                      │
│  · 这是绝大多数用户会停在的地方                        │
└─────────────────────────────────────────────────────┘
                        │
                        │  保留扩展空间
                        ▼
┌─────────────────────────────────────────────────────┐
│  副产品：一套可自定义的框架                            │
│  · 为"想改成自己风格的人"留的空间                      │
│  · 默认主题本身就是框架的第一个内容                     │
│  · 不要求用户使用                                    │
└─────────────────────────────────────────────────────┘
```

**设计原则**：

| 原则 | 说明 |
|---|---|
| **默认必须好看** | 用户什么都不做的时候，产品就是完整的。框架能力不能成为"半成品"的借口 |
| **框架是可选深度** | 不用的用户永远不该感知到它的存在 |
| **脏活给 Agent** | 用户只收集素材，适配由 Agent 完成（见 §3） |
| **默认主题即范例** | Boujoy 主题就是用这套框架做出来的，是活文档 |

## 2. 三档用户体验

| 档位 | 用户要做什么 | 得到什么 | 需要读文档吗 |
|---|---|---|---|
| **① 默认** | 装插件 | 完整的 Boujoy 主题 | ❌ 不需要 |
| **② 换素材** | 把素材丢进 `$DSH_HOME/boujoy/inbox/`，对 Agent 说一句"用这些给我配一套" | 自己的品牌外观 | ❌ 不需要（Agent 有说明书） |
| **③ 精调** | 手改 `boujoy.config.yml` / 写 `overrides.css` | 完全控制 | ✅ 需要 |

**档位 ② 是本项目的关键创新**——它把"理解槽位规格"这件事从用户转移给了 Agent。

### 2.1 为什么不做"按模板填素材"

最初的设想是"同名覆盖"：用户把文件命名成 `logo.svg`、`background.png` 放进指定目录。

**问题**：这要求用户先知道**有哪些槽位**、**每个槽位叫什么**、**什么格式**、**什么尺寸**。
对普通用户（"我是小白"）来说，这个前置学习成本比想象中高。

**改为**：用户随便丢，Agent 看内容判断。

| | 同名覆盖 | Agent 适配 |
|---|---|---|
| 用户要知道槽位表 | ✅ 必须 | ❌ 不需要 |
| 用户要正确命名文件 | ✅ 必须 | ❌ 随意命名 |
| 用户要懂格式要求 | ✅ 必须 | ❌ Agent 处理并提示 |
| 用户要写配置 | ✅ 必须 | ❌ Agent 生成 |
| 出错概率 | 高（静默不生效） | 低（有校验与报告） |

## 3. 职责划分

| 角色 | 负责 |
|---|---|
| **用户** | 收集素材，丢进 `inbox/`。就这一件事 |
| **Agent** | 看素材 → 判断归属 → 生成配置 → 校验 → 报告（能力见 `skills/boujoy-theme-setup/`） |
| **插件引擎** | 槽位规格、校验器、诊断、加载、降级、默认素材 |

**这意味着插件必须提供**：

1. **机器可读的槽位规格**（Agent 的适配依据）
2. **校验器 / 诊断能力**（不能只靠 Agent 自称"配好了"）
3. **随插件分发的 Skill**（让任何装了插件的 DSH 都具备适配能力）

## 4. 能力矩阵

| # | 能力 | 用户怎么用 | 自由度 | 状态 |
|---|---|---|---|---|
| 0 | **默认主题** | 装上即可 | — | ⬜ |
| 1 | 换 logo / 字标 | 丢进 inbox，让 Agent 配 | 完全 | ⬜ |
| 2 | 换配色 | Agent 从素材提取；或一句"主色用 #xxx" | 完全 | ⬜ |
| 3 | 细粒度改 token | 配置里写 `colors.tokens` | 完全（14 项） | ⬜ |
| 4 | 换字体 | 丢进 inbox（woff2） | 完全 | ⬜ |
| 5 | 换背景 / 纹理 | 丢进 inbox | 完全 | ⬜ |
| 6 | 调开屏时长/可跳过性 | 对 Agent 说，或改配置 | 完全 | ⬜ |
| 7 | 开关各类动效 | 同上 | 完全 | ⬜ |
| 8 | 调对话动效节奏 | 同上 | 完全 | ⬜ |
| 9 | 调氛围强度 | 同上 | 完全 | ⬜ |
| 10 | 改产品名/副标题 | 同上 | 完全 | ⬜ |
| 11 | 逃生舱：任意 CSS | 写 `overrides.css` | 无限 | ⬜ |
| 12 | 自定义面板/卡片 | 写插件（面向开发者） | 完全 | ⬜ |

> 能力 0–11 对用户**零代码**，其中 0–10 **连配置都不用写**。

## 5. 用户目录结构

```
$DSH_HOME/boujoy/
├── inbox/              ← ★ 用户唯一需要管的目录
│   └── <随意命名的素材文件>
├── assets/             ← Agent 适配后的产物
├── boujoy.config.yml   ← Agent 生成的配置
├── overrides.css       ← 高级：逃生舱
└── .history/           ← Agent 改动前的备份
```

**用户目录永不被动**：插件升级不覆盖、卸载不删除。

---

## 6. 优先级规则

一句话：**越具体越优先，用户永远压过内置。**

```
overrides.css
  → 配置里的具体 token
    → 配置里的简写（colors.brand）
      → 用户 assets/
        → 插件内置 assets/
          → 内置默认值
```

---

## 7. 失败降级

| 故障 | 界面表现 |
|---|---|
| 配置语法错 | 用内置默认外观 + 一次性提示 |
| 单字段非法 | 只有该项回退默认 |
| logo 损坏 | 回退内置 logo；再无则隐藏 |
| 字体加载失败 | 回退官方字体 |
| Agent 适配中断 | 幂等续做，既有产物不被破坏 |
| DSH 版本超范围 | **宿主跳过整个 bundle，恢复官方界面** |

**底线：任何问题都不得让界面白屏或不可用。**
