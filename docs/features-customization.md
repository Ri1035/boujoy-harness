# features-customization.md —— 高度自定义框架：能力说明

> 本文件回答：**用户到底能自定义到什么程度？** 以及每个能力的实现状态。
>
> 状态标记：✅ 已确定设计 ｜ ⬜ 待实现 ｜ ⚠️ 实现时需验证

---

## 1. 一句话定位

本项目**不是一套固定皮肤，而是一个界面框架**：

> 用户提供素材 + 改一个配置文件 → 得到完全属于自己的界面。
> 不改代码、不重启、不担心插件升级覆盖自己的东西。

---

## 2. 能力矩阵

| # | 能力 | 用户怎么用 | 自由度 | 状态 |
|---|---|---|---|---|
| 1 | **换 logo / 字标** | 把 `logo.svg` 放进 `$DSH_HOME/boujoy/assets/` | 完全 | ⬜ |
| 2 | **换配色** | 配置里写 `colors.brand: "#xxx"` | 完全 | ⬜ |
| 3 | **细粒度改任一 token** | 配置里写 `colors.tokens: { --dsw-alias-*: {light,dark} }` | 完全（107 个） | ⬜ |
| 4 | **换字体** | 放 `.woff2` + 配置指向它 | 完全 | ⬜ |
| 5 | **换背景 / 纹理** | 放图片 + 配置指向它 | 完全 | ⬜ |
| 6 | **调开屏时长/可跳过性** | `motion.splash.duration` / `.skippable` | 完全 | ⬜ |
| 7 | **开关各类动效** | `motion.*.enabled` | 完全 | ⬜ |
| 8 | **调对话动效节奏** | `motion.conversation.messageEnter` | 完全 | ⬜ |
| 9 | **调氛围强度** | `motion.ambience.intensity` | 完全 | ⬜ |
| 10 | **改产品名/副标题** | `name` / `subtitle` | 完全 | ⬜ |
| 11 | **逃生舱：任意 CSS** | `overrides.css` | 无限 | ⬜ |
| 12 | **自定义面板/卡片** | 注册自己的 slot | 需写代码 | ⬜ |

> 能力 1–11 **全部零代码**。能力 12 属于插件开发范畴，见 [`component-api.md`](./component-api.md)。

## 3. 三个层次的自定义深度

按用户投入从低到高：

### 层次 1：换素材（几分钟）

把文件丢进 `$DSH_HOME/boujoy/assets/`，**同名即覆盖**。

```
assets/logo.svg              ← 换掉就是新品牌
assets/fonts/brand.woff2     ← 换掉就是新字体
assets/textures/background.png
```

不需要改任何配置，只要文件名对。

### 层次 2：调配色与动效（十几分钟）

编辑 `$DSH_HOME/boujoy/boujoy.config.yml`：

```yaml
name: "My Harness"
colors:
  brand: "#3ba7ff"
motion:
  splash:
    duration: 3.0
    skippable: true
```

### 层次 3：完全自由（需要一点 CSS 知识）

在 `$DSH_HOME/boujoy/overrides.css` 里写任意 CSS。
它会被注入到页面，**优先级最高**，可以覆盖本项目自己的样式。

> ⚠️ 但它**不能突破 DSH 官方的禁止项**：菜单材质（`--dsw-menu-*`）等
> 官方明确禁止覆盖的 token 不建议动（见 [`DESIGN.md`](./DESIGN.md) §3.5）。

## 4. 为什么不直接改源代码

| 做法 | 结果 |
|---|---|
| ❌ 改 `app.asar` | 打包归档只读，DSH 更新即被覆盖 |
| ❌ fork 本项目改源码 | 每次上游更新都要手工合并；素材与代码混在一起 |
| ✅ **本项目的做法** | 代码是"渲染器"，素材与配置是"数据"。**数据放独立目录**，互不干扰 |

**核心设计**：把「引擎」和「内容」彻底分离。

```
引擎（本项目代码）        内容（用户目录）
  │                        │
  │  读取 ←───────────────┘
  │
  └─ 渲染出界面
```

升级引擎不会碰内容；换内容不需要动引擎。

---

## 5. 优先级的完整规则

同一份素材/配置，多处来源时的胜负：

| 优先级 | 来源 | 会被谁覆盖 |
|---|---|---|
| 4（最高） | `overrides.css` | — |
| 3 | 用户配置里的 `colors.tokens` | 被 overrides.css 覆盖 |
| 2 | 用户配置里的 `colors.brand` 等简写 | 被上一项覆盖 |
| 1 | 用户 `assets/` 里的素材文件 | 被配置里的显式路径覆盖 |
| 0（兜底） | 插件内置 `assets/` 与内置默认配色 | 被以上所有覆盖 |

**规则一句话**：**越具体越优先，用户永远压过内置。**

## 6. 用户目录的独立性保证

| 保证 | 说明 |
|---|---|
| 插件升级**不覆盖** `$DSH_HOME/boujoy/` | 该目录在插件包之外 |
| 插件卸载**不删除** `$DSH_HOME/boujoy/` | 用户素材保留，重装即恢复 |
| 用户文件损坏**不导致崩溃** | 逐项降级到内置默认（见 §7） |
| 配置错误**有明确报错** | 指出字段与行号，其余设置照常生效 |

---

## 7. 失败降级行为

| 故障 | 界面表现 |
|---|---|
| 配置文件语法错 | 用内置默认外观，顶部一次性提示 |
| 某个颜色值非法 | 只有那一个颜色不对，其余正常 |
| logo 文件损坏 | 回退内置 logo；再无则隐藏该位置 |
| 字体加载失败 | 回退 DSH 官方字体 |
| 背景图过大 | 仍加载，但建议用户压缩（warn） |
| DSH 版本不兼容 | **安全模式**：只应用配色，不注入 CSS、不播动画 |

**底线：任何自定义内容出问题，界面都必须可用。**

---

## 8. 与"主题插件"的关系

| 说法 | 是否准确 |
|---|---|
| "这是一个主题" | 部分准确——默认状态确实是一套完整主题 |
| "这是一个主题框架" | ✅ 更准确——主题只是它的默认内容 |
| "这是一个 UI 引擎" | 略夸大——它不做布局重写（不做 C 层的整布局替换） |

**准确的描述**：一个**以主题为默认内容的、素材与配置驱动的界面自定义框架**。
