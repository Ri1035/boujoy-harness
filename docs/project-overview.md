---

## 1. 一句话定义

**Boujoy Harness 是一个给 DSH（DeepSeek Harness）用的界面主题插件**，
通过 DSH 官方插件机制实现「开屏动画 + 风格界面 + 对话动画」，
**不修改 DSH 任何核心源码**。

---

## 2. 为什么要做

DSH 原生的界面是通用风格。用户希望把它变成属于自己的产品形态：

- 启动时有完整的品牌片头感，而不是一闪而过的 "Loading plugins…"
- 整体视觉有自己的配色、字体、氛围，而不是默认外观
- 对话流有动效节奏，而不是静态堆叠

市面上有类似项目（如终末地风格、QQ2006 皮肤、透明玻璃等），
但它们大多停留在旧版本 DSH、或强绑第三方插件、或直接 hack DOM。
本项目要走**官方接缝优先、可维护、可卸载**的路线。

## 3. 目标（可验收）

### 3.1 开屏动画

| 编号 | 验收标准 |
|---|---|
| G1.1 | 从应用导航到首帧，**不出现** DSH 自带的 `[data-dsh-boot]` "Loading plugins…" 卡片 |
| G1.2 | 开屏时长可配置，有明确的入场与退场动画 |
| G1.3 | 刷新页面 / 切换会话**不重复播放** |
| G1.4 | 三条退出路径：应用就绪 / 加载失败态 / 绝对超时 |
| G1.5 | `prefers-reduced-motion` 下自动降级 |
| G1.6 | 可跳过或可在设置里关闭 |

### 3.2 风格界面

| 编号 | 验收标准 |
|---|---|
| G2.1 | 全量配色覆盖，明/暗/跟随系统三种模式都无对比度问题 |
| G2.2 | 品牌字标替换（侧栏 logo 与产品名） |
| G2.3 | 背景氛围层（自有素材） |
| G2.4 | 圆角 / 阴影 / 材质体现自有视觉语言 |
| G2.5 | 自有字体接入（授权明确） |

### 3.3 对话动画

| 编号 | 验收标准 |
|---|---|
| G3.1 | 助手消息有入场动画 |
| G3.2 | 流式输出过程有节奏动效 |
| G3.3 | 工具调用卡片展开/收起有缓动 |
| G3.4 | **不影响**官方滚动跟随行为（流式时不乱跳） |

## 4. 范围

### 4.1 做什么（In Scope）

- 一个可安装的 DSH bundle 插件（npm 包形态）
- 主题 token 覆盖（A 层）
- 开屏动画（host 首帧 + client overlay，B 层）
- 品牌素材与氛围层（B 层）
- 已有一组件的视觉覆盖（C 层，受选择器分级纪律约束）
- 对话动效（C+ 层）
- 完整文档（本套 docs）

### 4.2 不做什么（Out of Scope）

| 不做 | 原因 |
|---|---|
| 改 DSH 核心源码或 `app.asar` | 更新会被覆盖，且破坏签名 |
| 整体替换 DSH 布局（占 `root` slot） | 官方禁止；要重声明约 90 个子 slot，产品层还可能反向启用官方行 |
| 替代桌面端（做自己的 Electron 壳） | 那是另一个项目；本项目只做插件 |
| 引入 UI 组件库 / Tailwind | 官方规范明确禁止（用 CSS Modules + clsx） |
| 依赖 `better-sidebar` / `shikitor` | 参考项目警告会双挂载；纯主题不需要 |
| 功能级扩展（新工具、新面板业务） | 这是主题项目，不是功能插件 |
| 修改用户数据 / 会话 | 插件只影响表现层 |

## 5. 交付形态

一个 npm 包（bundle），结构遵循 DSH 官方规范：

```
boujoy-harness/                     # 仓库根
├── README.md
├── AGENTS.md                       # AI 协作入口
├── docs/                           # 本套文档
├── research/                       # 调研资料（PLAN.md / REPORT.md + 参考项目源码摘录）
└── <插件包目录>/                    # 待 P0 建立
    ├── package.json                # 声明 dsh.bundle.patch + dsh.client.platform="web"
    ├── cordis.patch.yml            # 插入 host 插件行
    ├── index.js                    # host 半边：素材路由 + 首帧注入
    ├── client.js                   # client 半边：token / overlay / 开屏 / CSS 注入
    ├── theme.css                   # 主题与视觉覆盖
    └── assets/                     # logo / 字体 / 纹理
```

> 目前的目录布局在 P0 阶段确定。根目录文档已按用户要求下沉到 `docs/`。

## 6. 技术选型摘要

| 项 | 选择 | 依据 |
|---|---|---|
| 插件机制 | DSH 原生 Cordis bundle | 官方支持，可安装/卸载 |
| 主题覆盖 | `ctx.theme.overrideTokens()` | 官方 API，传 `{light,dark}` 对 |
| 开屏首帧 | host `ctx.on('webserver/index-inject')` | 唯一能覆盖 271ms 空窗的方式 |
| 开屏正片 | client `shell.overlay`（list slot） | 官方明确推荐的"自有全屏浮层"位置 |
| 素材分发 | host `webServer.register({kind:'prefix'})` | 白名单路由，可控 |
| 样式方案 | 纯 CSS + `bj-*` 命名空间 + CSS 变量 | 官方规范（禁 Tailwind/组件库） |
| 构建 | 纯 JS（无 TS 编译链），CSS 手写 | 参考项目 endfield 即纯 JS，省掉双 program 编译复杂度 |

## 7. 主要风险（详见 PLAN.md 风险登记册）

| 级别 | 风险 |
|---|---|
| 🔴 高 | **没有任何参考项目声明支持 0.2.0-rc.2**（最高验证到 rc.1） |
| 🔴 高 | 开屏 271ms 空窗——方案做错就永远漏出 DSH Loading 卡片 |
| 🟠 中 | 对话动画会撞上官方滚动跟随管线，需要额外补偿 |
| 🟠 中 | CSS 覆盖随 DSH 版本升级会碎（靠选择器分级纪律控制） |
| 🟡 低 | 素材/字体授权（影响能否公开分发） |
| 🟡 低 | 刷新重复播放开屏 / 重复注入 `<link>` |

## 9. 术语表

| 术语 | 含义 |
|---|---|
| **DSH** | DeepSeek Harness，AI 编码代理应用 |
| **bundle** | 带配置层的 npm 包，声明 `dsh.bundle.patch`，回答"贡献什么" |
| **profile** | `$DSH_HOME/profiles/<name>` 目录，声明 `dsh.profile.bundles`，回答"由哪些 bundle 组成" |
| **cordis** | DSH 使用的依赖注入框架 |
| **slot** | 类型化 React 组合系统的插槽；UI 扩展的唯一正道 |
| **A/B/C 层** | 本项目对改造深度的分层：token / 素材与浮层 / CSS 覆盖 |
| **patch 层** | `cordis.patch.yml` 里的补丁条目；**整行替换，不深合并** |
| **271ms 空窗** | DSH 开机卡片出现（67ms）到 client 插件就绪（338ms）之间的不可覆盖期 |
